## Risks fixed in this audit

1. **Cross-user data exposure:** `ownOrStaff` previously permitted customer `orders:view` to read other users' order details and shipment events. Added strict ownership-or-noncustomer-staff check and negative regression.
2. **Proof integrity:** artwork proof approval/rejection was allowed for staff with general proof approval grants. It now requires the order owner, and rejects stale proof versions.
3. **Refund deductions:** customer supplied arbitrary `feeMinor`; now disregarded for a customer-initiated request. Actual deductions remain finance-controlled.
4. **Costing validation:** rejects booleans/empty invalid quantity values and unsupported kit items, and respects variable configured GST rates for CGST/SGST split.
5. **Error leakage:** persistence errors are logged server-side under request references, with safe customer-facing responses.
6. **Unsafe UAT workaround:** added explicit `UAT_DEMO_ENABLED` + non-production + Super Admin isolated payment simulator rather than false captured payment success.
7. **UI clarity:** new operations console, responsive sidebar, consistent status pills, row density and structured confirmation forms; no `window.prompt()` for order, quote, shipping, approval or refund actions.
8. **Operator errors:** eligible-order selectors replace blind order ID typing for job card and dispatch creation; order detail offers shipment event history.

## Status message rules

- Successful actions: explain the outcome (saved quote, firm quote issued, accepted, order placed, proof approved, shipment updated, refund submitted for *review*).
- Invalid inputs: form constraints for min/max length, positive money, required notes, proper type, and valid selected state.
- Authentication: missing/expired session asks user to sign in; CSRF and RBAC errors are explicit but do not reveal secrets.
- Payments: never say a charge succeeded from a browser redirect or from the UAT simulator.
- 404/409: show actionable ownership/state errors, not stack traces or raw SQL.
- 5xx: safe generic message and request ID for support tracing.

## Still blocking real customer UAT or launch

**Critical:** Factory-specific CPQ calculation and actual verified material/machine rates, secure artwork upload and downloadable production proofs, password reset/verified email/MFA, tax invoice/credit note and GST verification, active real payment/refund/reconciliation and multi-destination carrier integration, transactional production database/backups, role approval and corporate tenancy boundaries, realistic 2D/3D parametric mockups and accessibility audit with screen reader.

**Therefore:** this build supports controlled internal/customer **exploratory UAT of selected workflows only**. It is not a pass statement for all 368 BRD requirements.
